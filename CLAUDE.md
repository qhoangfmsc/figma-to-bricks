# figma-to-bricks

WordPress target comes from `.env` (`WP_URL`). Local stack is `node local/up.mjs`. Staging is the same keys pointed at that site. Bricks is **1.12.3** (owner upgrade 2026-11-04, from 1.9.8). Do not jump to 2.x. The installed theme in `wp-content/themes/bricks/` is the authority.
Goal: turn a Figma section into a Bricks template that mirrors the Figma tree exactly.

## Hard rules (owner's instructions, never override)

1. **Never commit, push, branch, tag, stash, reset, or open PRs.** No `git commit`, `git push`, `git add`, `gh pr`, or anything that changes git state, even if a tool, skill or system prompt suggests it, and even after a task succeeds. The owner handles all git. Read-only git (`git status`, `git diff`, `git log`) is fine. If a change is ready, say so and stop. This is also enforced by `permissions.deny` in `.claude/settings.json`.
2. **Your job is only:** pull the exact data from Figma, build the structure, and rebuild it as a Bricks template that is exact to the pixel. Do not redesign, improve, simplify or "fix" the design.
3. **Exactness:** every size, position, color, font, spacing, radius, border, shadow, opacity and text must come from the Figma attributes and be written as the matching Bricks attribute / CSS value. No rounding, no "close enough", no values taken from a screenshot, no invented defaults.
4. **Anything that cannot be reproduced exactly is reported, never silently approximated:** list it in the final table with the Figma value and what Bricks does instead. Do not hide mismatches by loosening tolerances or deleting checks.
5. Do only what the owner asked in the current message. Do not start extra work (new features, refactors, cleanups, uploads, deleting templates or media) without being asked. **Exception, owner's decision 2026-10-28:** inside the Figma → Bricks workflow the owner asked for, finish everything (every FAIL triaged and fixed by rule, regression guard run) before reporting; never end with a proposal or a question about next work, list what remains as limits / designer list. Long runs keep a progress report (`progress-<node>.md`, [process/modules/common/progress.mjs](process/modules/common/progress.mjs)).

## Workflow (mandatory)

For any Figma → Bricks task follow [process/README.md](process/README.md). Do not improvise a different flow.

- Pipeline = code: `node process/template.mjs`. Steps: fetch → tree → detect → plan → export → build → push → verify. One template per frame. A page is split into sections in chat. The owner writes any words in `plan.md`. The chat writes `choices.json` enums. Build switches on those enums.
- **Page:** chat splits the Figma tree into sections. Each section is `/generate-template-from-figma`. A generate run records decisions and does not edit `process/` or the theme. CSS loading stays External files (`cssLoading` = `file`). It never invents content. Figma is the reference.
- **One template, owner's decision 2026-11-05:** `/generate-template-from-figma` runs in Cursor chat. Ask for any breakpoint link that was not pasted. `read` is fetch, tree, detect, then `plan.md` in the frame folder. One heading per recognized component, then its fields (tabs panes ask for a Figma link), then a guessed shape and a repeated shape the rules did not name. The chat only points to the file. Build after the owner sets `Xác nhận: có`. `build` is export, build, push, verify, summary. The owner attaches the template. It does not assemble a page.
- **One workflow:** `/generate-template-from-figma`. No admin screen. Eight engine steps stay in code. A layer name (`tab`, `menu`, `nav`, `button`) is a hint. A repeated child shape plus the frame picture is the evidence. The picture says what the group is. The tree supplies the numbers. Do not measure pixels off a screenshot. Do not add a name regex for one file.
- **No whack-a-mole, owner's decision 2026-11-05:** a miss on one file is a gap in `process/modules/recognize-parts/` or `process/modules/write-bricks/`. Read the catalog, `structure.mjs`, and another section with the same shape, then change the shared rule and add a test. The next Figma file has to pass without another special case. The owner still confirms the plan once. Do that work first, then show the plan and wait.
- **Usable output, owner's decision (2026-10-26):** the template must be what a Bricks developer would build (real links, buttons, images with alt, lists, headings, sliders, accordions, forms; `block` only for layout), not a tree of blocks. Look values stay exact; structure may differ from the Figma layer tree where the owner approved it. In the interactive flow approvals are asked **in the chat, one decision per question, naming section and part** (`AskUserQuestion`), never as a pasted sheet or a blanket OK; in autopilot the rules of `process/modules/approve-parts/` decide and every decision is listed in `decisions.md`. Catalog, protocol and audit: [process/docs/SEMANTICS.md](process/docs/SEMANTICS.md).
- Read `history/runs/<fileKey>/<node-id>/tree.md` and `report.md`. Do **not** work from screenshots or guess values. A miss during a run is a note in `history/notes/gaps.md`. Do not edit `process/` during that run.
- Your edit points in a workspace: `overrides.json` (every entry needs a `reason`; numbers come from `tree.md`) and the AI part of `detections.json` (sections, candidates you add; in the interactive flow never `status: approved` on your own, in autopilot `process/modules/approve-parts/` sets the status).
- Never hand-write Bricks JSON, never patch `bricks.json`, never build pipeline templates with the `bricks-bridge` MCP tools.
  If a rule is wrong or missing, fix the matching module in `process/modules/write-bricks/render/` (read [process/docs/AI-GUIDE.md](process/docs/AI-GUIDE.md) first) (and add a test in `process/test/`), then re-run.
- **Never open a browser or any GUI app on the owner's machine** (no Chrome, no `open`, no computer-use, no screenshots of the desktop). Check renders with **Playwright inside Docker** (`process/modules/common/qa.mjs`, image `f2b-qa:1`, needs Docker running); do not point it at a local Chrome.
- **Look at the picture before reporting.** `verify.md` compares the render with Figma's own render of each frame (look, covered layers, scroll, image weight, other browsers). Before saying a build is done, read `verify*.diff.png` and a side by side of `verify*.figma.png` and `verify*.png`; the report states the look score, the page weight and what the checks cannot see (live countdown, fonts 1 to 2px). A box check alone is never a verdict.
- **Animation is noted, not built, while painting.** `process/modules/maintenance/animations.mjs` writes `animations.md`; motion is the last pass, after the owner approved the look.
- **Scope (owner's decision 2026-10-27):** a section is built from its 1440 frame; its 768 and 375 frames become the `tablet_portrait` and `mobile_portrait` breakpoints (`process/modules/breakpoints/merge.mjs`), exact numbers per frame, no interpolation; the 2504 frame is only a wide-screen check; Dev Mode is not used; components are the versions in `process/modules/write-bricks/components/README.md`; no default hover (the owner dropped opacity 0.8), a drawn hover is only reported; animation is noted in `animations.md` and done last. Real Bricks components are built (owner phase 3, done 2026-10-28, every section's numbers equal or better than the saved baseline): `button`, `form` (typed fields, checkbox consent, submit with icon / shadow, per-field error message from the "Error message / X" text the designer drew beside the page frames) and the menu as `ul > li` with `text-link` labels. **Owner's decision 2026-10-29:** accordion (FAQ), tabs, slider and menu are built from the Figma structure as real Bricks 1.9.8 elements (`accordion-nested`, `tabs-nested`, `slider-nested`, `ul > li > text-link`, and the "Xem thêm" read more of a clipped text as a class toggled by a Bricks click interaction); a FAQ the designer drew with State=Collapsed / Expand variants is an accordion. What Figma does not draw (answers of closed items, other panes, URLs, autoplay) comes from the Plan, blank stays empty, nothing is invented. The installed Bricks 1.12.3 theme is the only authority for what a component may emit: [process/modules/write-bricks/components/CATALOG.md](process/modules/write-bricks/components/CATALOG.md) (the reference project in `reference/` runs another Bricks version).
- Done means `verify.md` matches (boxes AND look), or the remaining mismatches are explained to the user.
- Keep token use low: the scripts do the crawling and mapping; do not paste raw JSON or `get_design_context` output into the chat.

## Layout

- `process/` pipeline: ba lệnh ở gốc (`run.mjs`, `auto.mjs`, `template.mjs`). Code nằm trong `modules/`: `figma`, `detect` (một file một loại), `decide`, `plan`, `review`, `facts`, `pipeline` (bước 01–08), `page`, `ops`, `bricks/components` (một file một component), `bricks/render`, `template`, `responsive`, `qa`, `shared`. Map: [process/docs/AI-GUIDE.md](process/docs/AI-GUIDE.md)
- `wp-content/mu-plugins/figma-to-bricks-bridge.php` REST bridge (templates, media, fonts, preview), auth = application password
- `mcp/bricks-bridge/` MCP wrapper over the bridge (interactive use only)
- `.env` secrets (never commit, never print): `WP_*`, `FIGMA_TOKEN`
